# D-Bus for Kotlin: options in 2026 (resurrecting dbus-kotlin)

Researched 2026-09-28, before touching any code. The repo was last touched in July 2021.

## What this repo is today

- `dbus-kotlin/src/jvmMain/kotlin/DBusKotlin.kt`, about 160 lines: thin helpers over **dbus-java 3.x**
  (`dbusConnect`, `getRO<T>`, a `suspendCoroutine` wrapper around `callWithCallback`), plus a few
  concrete calls: GNOME Mutter `DisplayConfig`, `org.freedesktop.ScreenSaver`, and NetworkManager
  wifi on/off.
- `Experiment.kt`, 336 lines: experiments, including an unfinished attempt at dynamic calls
  without code generation (a FIXME says it doesn't work).
- `dbus-generated/`: Java interfaces generated by dbus-java's `InterfaceCodeGenerator`.
- The build uses the pre-2021 `deps.kt` API (`Vers.kotlin`, `Deps.dbusJava`, `Repos.jitpack`),
  none of which exists in current DepsKt. It also publishes via jitpack.

Also relevant: the desktop has since moved from GNOME to Hyprland (DMS), so the Mutter
`DisplayConfig` part no longer has a use on myxps. NetworkManager and the portals are still there.

## Options

### A. sdbus-kotlin: recommended

[Monkopedia/sdbus-kotlin](https://github.com/Monkopedia/sdbus-kotlin), `com.monkopedia:sdbus-kotlin`
1.0.1 on Maven Central (2026-07).

- **Kotlin Multiplatform:** `jvm` (a pure-Kotlin marshaller over junixsocket, with no native
  code) plus `linuxX64` and `linuxArm64` (sd-bus via cinterop). The same common API on all targets.
- **Coroutines:** generated proxy methods are `suspend`, and properties expose a `Flow`
  (`values()` / `changes()`). This is exactly what `dbusCall` + `suspendCoroutine` were
  hand-rolling here.
- **Code generation:** a Gradle plugin (`com.monkopedia.sdbus.plugin`) generates Kotlin proxies
  and adaptors from introspection XML, into `commonMain` if wanted. It would replace
  `dbus-generated/` (Java) and `DBusKotlinGenerator.kt`.
- **Stability:** 1.0 froze the API, and it's enforced in CI by the binary-compatibility-validator.
  Actively developed (last push 2026-08), 41 open issues.
- **Caveats:** a small project (16★, one maintainer), and **LGPL-3.0** (dbus-java is MIT). Linking
  an LGPL lib from an Apache-2.0 repo is fine; just be aware of it.

It also matches the direction of KGround and luagnd: multiplatform and linuxX64-capable, so a
native CLI could use D-Bus without a JVM.

### B. dbus-java 5.x: the conservative port

[hypfvieh/dbus-java](https://github.com/hypfvieh/dbus-java), 5.2.2 on Maven Central (2026-09-26),
actively maintained, MIT.

- JVM only. The transport is now a separate artifact (`dbus-java-core` +
  `dbus-java-transport-native-unixsocket` or `-junixsocket`).
- **API breaks from 3.x:** `DBusConnection.getConnection(...)` was replaced by
  `DBusConnectionBuilder`, and packages moved. The existing helpers would need rewriting,
  and the generated Java interfaces regenerating.
- There's no coroutine story; this repo would keep providing it.
- Used underneath by [zugaldia/stargate](https://github.com/zugaldia/stargate) (see D).

### C. No library: the CLI via kommand-line

Call `busctl` / `gdbus` through KGround's kommand-line, which is already how Marek drives the
system from Kotlin. Zero dependencies, fine for a handful of one-off calls, but untyped and
string-parsed, with no signals or property flows. Good for scripts, not as a library.

### D. Specialized libraries, if the goal is narrower

- [zugaldia/stargate](https://github.com/zugaldia/stargate) (MIT, JVM 25): typed XDG Desktop
  Portals (screenshot, clipboard, …) plus StatusNotifierItem tray icons, on dbus-java 5.
- [kdroidFilter/DbusTrayKt](https://github.com/kdroidFilter/DbusTrayKt) (MIT): tray icons only.

## Recommendation

**A (sdbus-kotlin)**, used underneath, with this repo reduced to what it actually adds:
Marek-specific typed shortcuts (NetworkManager, ScreenSaver, portals, maybe Hyprland-relevant
services) as a small KMP lib (jvm + linuxX64) on the DepsKt templates, with the proxies generated
from XML by the sdbus plugin.

Suggested order:
1. Decide what dbus-kotlin should be *for* now. The GNOME Mutter use case is gone. If nothing
   concrete needs it, archive the repo instead of porting it.
2. If yes: a new build on `defaultBuildTemplateForBasicMppLib` (jvm + linuxX64), add
   `sdbus-kotlin` + the sdbus plugin, drop `dbus-generated/` and the jitpack publishing, and
   rewrite `DBusKotlin.kt` on top of the generated proxies. Keep `Experiment.kt` out or delete it.
3. Would it make sense to add `sdbus-kotlin` to DepsKt? Only once a second consumer appears.
